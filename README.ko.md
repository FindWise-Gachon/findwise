# FindWise

**[English](README.md) | [한국어](README.ko.md)**

**실종자 위치 확률 예측과 AI 기반 현장 정보 통합을 활용한 수색 의사결정 지원 시스템**

FindWise는 산악 실종 수색에서 **어디를 먼저 찾아볼지**, **현장 보고를 받은 뒤 수색 계획을 어떻게 조정할지** 판단하도록 돕는 프로젝트입니다. 마지막 확인 위치·경과시간·지형정보로 위치 확률 지도를 만들고, 수색 중 들어온 정보를 사람이 검토한 뒤 지도에 반영하는 것을 목표로 합니다.

## 개발 배경

수색 초기에는 실종자의 위치를 특정하기 어렵고, 수색이 진행되면 미발견 보고·단서·위험 정보가 계속 추가됩니다. 초기 예측과 현장 정보를 하나의 지도에서 함께 확인하고, 판단에 필요한 정보 정리 부담을 줄이고자 합니다.

실종자 발견이나 사건 해결을 자동으로 확정하는 시스템이 아니라, 사람의 판단을 지원하는 도구입니다. 경찰행정학과 교육·실습에서 수색 과정을 체험하고, 향후 다른 분석 기능과 연결할 수 있는 구조를 지향합니다.

## 프로젝트 목표

- **위치 확률 예측:** 마지막 확인 위치 또는 후보 범위, 경과시간, 지형을 이용하여 거리·지형·간소 행동 모델을 비교합니다.
- **지도 시각화:** 위성·등고선 등 지도 레이어 위에 위치 확률 히트맵과 수색 현황을 표시합니다.
- **현장 정보 통합:** 한국어 텍스트 무전·보고를 AI로 구조화하고, 사람이 수정·승인한 내용만 지도 갱신에 사용합니다.
- **판단 근거와 이력:** 원문, 검토 내용, 지도 변경을 기록하여 추천 근거와 변경 과정을 확인할 수 있게 합니다.
- **평가와 교육 활용:** 모델 비교, 보고 해석 품질, 지도 갱신의 정확한 동작과 사용성을 검증하고 교육용 시나리오로 활용합니다.

## 목표 사용 흐름

```text
마지막 확인 위치·시간·지형 입력
  → 초기 위치 확률 지도
  → 현장 보고 입력·AI 해석
  → 사람의 검토·수정·승인
  → 지도 및 수색 우선지역 갱신
  → 변경 이력을 참고해 다음 수색 판단
```

## 설계 원칙

**확장성:** 요세미티와 한국 지역, 지도·데이터 제공처, 예측 모델, AI 제공 업체를 변경할 때 공통 화면과 업무 흐름을 재작성하지 않도록 설정과 기능을 분리합니다. 필요한 모듈을 추가하되 초기부터 다수의 서버나 저장소로 분리하지 않습니다.

**직관성:** 배경지도 선택과 독립 레이어 토글을 구분하고, 보고의 검토 상태와 지도 변경 이유를 명확히 보여줍니다. 사용자가 분석 결과를 확인하고 다음 행동을 결정하는 흐름을 중심으로 설계합니다.

## 저장소 구조

```text
frontend/    웹 화면·지도·레이어 조작
backend/     지형 전처리 CLI와 향후 분석·보고 API
data/        로컬 자료·공개 예제·출처 기록
docs/        개발환경 안내
.github/     PR 검사
```

폴더를 기능마다 과도하게 늘리지 않고, frontend와 backend 내부에서 실제 구현에 필요한 만큼 나눕니다.

## 개발 상태와 시작 방법

상단 작업 지역에서 요세미티와 북한산을 오갈 수 있습니다. 두 지역에서 기본·위성 지도와 등고선·음영기복을 표시합니다. 기본 투영 격자는 6 × 6km 개발 영역을 6m 셀로 나눕니다. 분석 범위를 표시하고 확대 수준 16 이상에서 화면에 보이는 격자선을 확인할 수 있습니다. 지역 정보 패널에서 격자 정의를 JSON으로 내려받을 수 있습니다. 확인 위치에서 지도에 지점을 선택·확정한 뒤 **오늘**·**어제**를 선택하거나 날짜를 직접 입력합니다. 24시간제 시각(예: `1430` 또는 `14:30`)을 입력하고 **시각 확정**을 누르면 분석 옵션이 열립니다. 로컬 개발 서버에서는 Ring과 ABM을 실행할 수 있습니다. **다른 분석 도구**에서 개발 격자 안의 거리 순위를 볼 수 있고, 거리 분석 조건은 JSON으로 내려받을 수 있습니다. 지도 자료 요청에서 오류가 보고되면 다시 시도할 때까지 경고를 표시합니다.

저장소 루트에서 [.nvmrc](.nvmrc)에 고정된 Node.js 22.21.1을 사용합니다.

```bash
nvm install
nvm use
cd frontend
npm ci
npm run dev
```

인터넷에 연결된 WebGL 지원 브라우저에서 Vite가 출력한 Local 주소를 엽니다. `frontend/`에서 `npm run lint`, `npm test`, `npm run build`로 확인합니다. GitHub Actions는 PR에서 같은 프런트엔드 검사를 실행합니다. `Backend checks`는 Python 3.13으로 `backend/tests`의 단위 테스트를 실행합니다. 로컬 설치와 테스트 명령은 [백엔드 README](backend/README.md)를 참고하세요. 로컬 개발에서 Docker는 선택 사항입니다.

지도 위에서 마우스를 움직이면 하단에 위도와 경도가 표시됩니다.

**확인 위치 → Ring 모델 실행**을 사용하려면 저장소 루트에서 Python 3.13 환경을 먼저 설치합니다.

```bash
python3.13 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
```

로컬 Vite 서버를 실행한 뒤 마지막 확인 위치와 시각을 확정하고 **Ring 모델 실행**을 누릅니다. 온대 산악 등산객 프로필로 거리 기반 확률 지도 한 장을 계산합니다. 경과 시간과 지형·통행 조건은 계산에 사용하지 않습니다. 지도는 개발 격자 안의 상대 확률을 표시하고 색 경계는 부드럽게 보간합니다. 격자 안에 들어온 전체 모델 확률의 비율은 별도로 표시합니다. Ring 실행 버튼은 로컬 개발 서버에서 제공되며 정적 빌드에서는 거리 순위와 결과 JSON 가져오기를 사용할 수 있습니다.

왼쪽 **거리 측정**에서 지도에 두 점 이상을 찍으면 구간별 수평 거리를 합산합니다. 다른 작업으로 전환하거나 측정선 표시를 꺼도 현재 측정은 남습니다. **새 측정 시작**으로 기존 측정선을 남긴 채 다른 위치에서 새로 시작할 수 있습니다. 각 측정에서 구간별 거리와 합계를 확인합니다. 측정은 페이지를 새로고침할 때까지 유지되며 고도 차이와 등산로 길이는 반영하지 않습니다.

로컬 개발 서버의 **확인 위치 → 분석 모델 → ABM · 행동 시뮬레이션**에서 무작위 보행 또는 높은 곳으로 이동, 1시간 또는 2시간, 지도 통행 조건 적용 여부를 선택합니다. 고정 시드의 512개 경로를 30분 간격으로 표시합니다. 계산이 끝나면 선택한 종료 시점을 먼저 보여줍니다. 슬라이더나 **시간 변화 재생**으로 시점을 바꾸고, 표시 중인 셀 확률을 바탕으로 마지막 확인점에서 평균 직선거리를 볼 수 있습니다. 지도에서 색이 부드럽게 퍼지는 효과는 표시용입니다. 높은 곳으로 이동과 선택적 경사 제한에는 정렬된 분석용 DEM이 필요합니다. 통행 조건을 사용한 결과에 버전이 기록되며 이후 수정하면 다시 계산해야 한다는 안내가 표시됩니다. 현재 조건에서 주변에 이동할 수 있는 셀이 없으면 결과 화면에 출발점에 머물렀다고 표시합니다.

자료·설정에서 LKP와 마지막 확인 시각이 포함된 모델 결과 JSON을 열면 시간 슬라이더로 계산된 시점을 전환합니다. 모든 시점에 같은 색상 척도를 사용합니다. 합성 예제와 [결과 형식 안내](frontend/README.md#시간별-결과-형식)를 제공합니다.

로컬 개발 서버의 **현장 보고**에서 수색 구역 중심과 반경, 보고 원문, 수색 시각을 입력하고 검토자 이름과 근거를 남겨 승인합니다. 승인된 기록은 같은 브라우저의 분석 격자·마지막 확인 위치·시각에 연결되어 새로고침 후에도 남습니다. **승인 기록**에서 **현장 보고 표시**를 켜고 승인 구역을 누르면 기록을 확인할 수 있습니다. 확률 갱신에는 개발용 탐지 확률 50%를 사용하며 선택한 ABM 시점에만 적용합니다. 동일 분석을 재실행하면 저장된 반영 결과를 복원하며 같은 보고를 다시 계산하지 않습니다.

**현장 보고 → 사건 흐름**에서 지도에 제보·CCTV·GPS 신호·수색 마커를 추가합니다. 지도 마커를 누르면 상세에서 삭제할 수 있으며 마지막 확인 위치도 지점 상세에서 지울 수 있습니다. 마지막 확인 위치, 마커, 현장 확인과 승인을 시간순으로 보며 항목을 눌러 위치나 기록을 확인합니다. 수색 마커에서 보고를 작성하면 위치·시각·메모가 채워집니다. 기존 보고 양식에서 반경·검토자·승인 근거를 확인하고 승인하면 선택한 ABM 시점에 반영합니다. 마커는 분석 범위 밖에도 남길 수 있습니다. 마지막 확인 정보가 없으면 이 브라우저에 임시 저장되고, 정보를 설정한 뒤 사건 흐름에서 해당 사건에 연결할 수 있습니다. 수색 보고는 분석 범위 안의 위치로 작성합니다.

GPS 마커에는 신호 출처와 위치 오차(m)를 기록할 수 있습니다. 검토자가 승인과 근거를 남긴 뒤 분석 범위 안의 신호를 마지막 확인 위치·시각으로 채택합니다. 사건 흐름에 채택 근거와 기존 기록이 남습니다. 분석 화면에서 채택한 위치와 시각으로 ABM을 다시 실행할 수 있습니다.

**분석 결과 → 현재 결과를 기준으로 저장**으로 ABM 원본을 기준 A로 잡습니다. 같은 마지막 확인 위치·시각·시드·경로 수로 다시 실행한 뒤 **기준과 현재 비교**를 누르면 두 지도가 함께 이동하고, 공통 시점과 색상 척도로 결과를 비교합니다. 기준은 페이지를 새로고침하기 전까지 유지됩니다.

**후보 구역**에서 분석 범위 안 두 모서리를 찍으면 격자 셀에 맞춘 사각형을 만듭니다. 비교표에서 면적과 현재 Ring 결과 또는 선택한 ABM 시점의 셀 확률 합을 확인합니다. 확률·면적·추가 순으로 정렬하고 행을 누르면 지도에서 해당 구역을 볼 수 있습니다. Ring 값은 분석 격자 안의 조건부 확률입니다. 마지막 확인 정보나 적용한 통행 조건이 바뀌어 결과가 오래되면 다시 실행해야 확률을 표시합니다. 후보 구역은 새로고침 전까지 유지됩니다. 선택한 시점에 승인된 수색 완료 보고가 있다면, 보고 한 건과 후보 구역을 골라 승인 직전·직후 확률과 변화 폭(%p)을 볼 수 있습니다. 변화 항목을 누르면 원문과 승인 정보를 볼 수 있고, **승인 기록**에서 해당 시점의 후보 변화로 돌아갈 수 있습니다.

**현장 보고 → 진입 불가**는 사람이 승인한 구역을 지도에 기록합니다. 같은 사건에서 수색 완료와 진입 불가 구역이 겹치고 현장 시각 차이가 60분 이하면 **함께 검토할 보고**에서 두 원문과 시각을 보여줍니다. 모델의 이동 제한은 별도로 통행 설정에서 관리합니다.

## 데이터와 평가

선택적으로 백엔드 지형 CLI를 실행해 수치 DEM을 지도에서 내보낸 격자에 정렬하고 경사와 유효 셀 마스크를 계산할 수 있습니다. [지형 CLI](backend/README.md), [요세미티 자료 카탈로그](data/catalog/yosemite.md), [평가 초안](docs/evaluation.md)을 참고하세요.

백엔드의 `backend/app/abm_reproduction/`은 Hashimoto 외(2022·2026)의 에이전트 기반 실종자 행동 모델을 재현합니다. 무작위 보행, 머물기, 높은 곳 오르기, 되돌아가기를 구현했습니다. 경로 따라가기, 방향 유지, 결정 지점, 등고선 따라가기는 아직 없습니다. 등고선 따라가기는 논문 본문에 임계값이 없어 부록의 정의를 확인한 뒤 추가합니다. [행동 전략 패키지](backend/app/abm_reproduction/strategies/README.md)를 참고하세요.

요세미티 시작점–발견점 자료는 이용 조건과 유효 사건쌍을 확인한 뒤 위치 예측 평가에 사용합니다. 실제 무전 기록이 없는 경우 보고 처리·지도 갱신 실험은 합성 시나리오로 분리합니다. 해외 평가 결과를 국내 성능으로 그대로 일반화하지 않습니다.

지역과 격자는 `frontend/src/map/regions.ts`에서 설정합니다. 북한산은 팀 시연 자료의 10m 격자와 등산로·하천, 고도·경사 표시 이미지를 사용합니다. 전달받은 `trails.geojson`, `waterways.geojson`, `elevation.png`, `slope.png`를 `data/raw/bukhansan-demo/`에 둡니다. 북한산의 고도·경사를 사용하는 분석에는 해당 격자에 정렬된 수치 DEM `data/processed/bukhansan-terrain.npz`가 필요합니다. 계산 격자 크기와 원본 고도자료 해상도는 구분합니다. 등고선은 표시용 레이어이며, 지형 분석에는 수치 고도자료를 사용합니다. 발견점 등 평가 정답은 예측 입력과 수색 범위 선정에서 제외합니다.

원본·가공 결과·캐시·평가 자료와 비밀 파일은 Git에서 제외합니다. 공개 합성 예제는 `data/samples/`에, 출처와 이용 조건은 `data/catalog/`에 기록합니다. 코드 라이선스는 팀 합의 후 정합니다.

지형 GeoJSON을 불러와 지도에서 이동 상태와 근거를 수정하고 공통 격자의 모델 입력으로 내보낼 수 있습니다. [지형 작업 흐름](backend/README.md#지형과-이동-조건)을 참고하세요.

복합 수역의 섬과 분할 경계를 보존하며, 모델은 미확인 처리 방침을 지정해 공통 8방향 이동 판정 함수를 사용할 수 있습니다.


기본 지형은 준비된 로컬 OSM 자료에서 자동으로 연결됩니다. 레이어 메뉴에서 등산로·도로·하천·호수 표시를 각각 켜고 끕니다. 지형을 클릭해 통행 막기·허용을 선택하고 이유를 적용합니다. 수정 이력은 이 브라우저에 자동 저장되며 직전 변경을 되돌릴 수 있습니다. 표시 토글은 모델 입력에 영향을 주지 않습니다. LKP와 시각도 별도로 저장하며, 지도 표시 초기화는 이 정보와 지형 수정을 보존합니다.

처음 받은 저장소에서는 [지형 작업 안내](backend/README.md#지형과-이동-조건)에 따라 `data/raw/yosemite-terrain-v2.geojson`을 준비합니다. 개발 서버가 이 자료를 제공하고, 빌드 시에는 별도 에셋으로 포함합니다. 원자료는 계속 Git에서 제외합니다. 자료가 없으면 다시 시도하거나 고급 설정에서 자료를 추가할 수 있습니다. 브라우저 저장은 접속 주소·포트와 기기별로 구분됩니다.

시간별 결과 JSON에는 `terrain_revision`을 기록할 수 있습니다. 해당 정보가 없거나 현재 지형 버전과 다르면 결과에 안내를 표시합니다. 마지막 확인 정보가 달라진 기존 결과도 표시합니다. 현재 거리 기준은 거리 순위이며, 합성 시간별 결과는 화면 확인에 사용할 수 있습니다.

왼쪽 메뉴는 확인 위치·분석 결과·통행 설정·수정 이력으로 구분하고, 파일 가져오기는 자료·설정으로 옮겼습니다. 지도에 찍은 점을 클릭하거나 키보드로 누르면 확인 시각·경과 시간·분석 상태와 주변 등산로·도로를 볼 수 있습니다. 주변 거리는 불러온 자료의 직선거리이며 이동 시간은 계산하지 않습니다.
